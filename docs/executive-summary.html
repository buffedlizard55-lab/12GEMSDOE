Do not submit yet

No candidate has passed the strongest-baseline gate. A range-valid file alone is not a scientifically qualified submission. There is intentionally no approved download today.

When an approved candidate is released

  1. On the workbench, download the approved .tif—not this HTML page, a PDF report, or the sample template. Its linked manifest must say it passed the fixed holdout gate.
  2. Check the unique filename, SHA-256 checksum, experiment identity, and short note. Renaming a file does not make it a different experiment.
  3. Open the official competition, sign in, review the current rules, and choose New submission.
  4. Select the GeoTIFF in “File to submit.” A ZIP is only appropriate if the current form permits it and contains one GeoTIFF. This project targets direct TIFF upload.
  5. Copy the approved manifest's short note into “Note.” Future format: 12GEMS [hypothesis]; [split/model]; sha [12 characters]. Do not use an unmeasured score in the note.
  6. Upload only after local validation passes and an available slot is confirmed. Save the receipt, exact uploaded hash, timestamp, note and resulting public score together. Do not automatically retry a rejected upload.

What the validator checks

One float32 band; CRS, width, height and affine transform exactly match the template; same footprint; finite [0,1] values inside; NaN outside. Invalid logits, percentages and negative nodata are rejected, not silently clipped.

The old “Predicted values must be in range [0,1]” error cannot be traced to a specific cause without its exact file. A new strict writer and regression tests prevent those classes of error locally.

Current access limitations

No DrivenData login, authenticated upload receipts, or hidden labels are available. The team-mirrored rasters have verified checksums but an unresolved sample-content discrepancy. Competition rules and eligibility require a full compliance check before release.
