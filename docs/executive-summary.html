Troubleshooting: The "Predicted values must be in range [0, 1]" Error

What the Error Does — and Does Not — Establish

The rejected file and DrivenData parser log were not retained, so this generic message does not identify the past root cause. The official format page requires one float32 band with values in [0, 1], the same CRS/resolution/bounds as training, and null or NaN outside the bounds. The checks below are local prevention checks, not an assertion about DrivenData’s parser.

  • Valid-footprint values: Check that every valid pixel is finite and in [0, 1].
  • Grid and mask: Check one band, float32 dtype, template CRS/shape/transform, and the project’s conservative NaN-outside convention. The official wording allows null or NaN outside bounds.
  • Package: Upload one GeoTIFF directly or a ZIP containing exactly one GeoTIFF, as stated in the form.

What is verified locally: scripts/core.py:validate() checks grid equality, one float32 band, finite in-range values inside the template mask, and NaN outside it. The archived file passes that local validator. DrivenData remains the final format arbiter.
