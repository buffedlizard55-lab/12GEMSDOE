Troubleshooting: The "Predicted values must be in range [0, 1]" Error

Root Cause of the Submission Form Rejection

When previous submissions returned Predicted values must be in range [0, 1], it was caused by one of three backend validation triggers:

  • Non-Finite Values Inside Footprint: Any pixel inside the valid 5,167,373 survey footprint that evaluates to NaN, +Inf, or -Inf causes DrivenData's parser to reject the file with this generic error message.
  • Finite Values Outside Footprint: If background pixels outside the survey boundary contain numbers (e.g. 0.0 or negative nodata like -9999) instead of strict NaN, the template mask comparison fails.
  • Out-of-Bounds Probabilities: Any unclipped raw logits ($<0$ or $>1$) trigger immediate range rejection.

How 12GEMSDOE Eliminates This Error: Our strict automated validator (scripts/core.py:validate()) asserts before packaging that every single valid pixel is strictly finite and $\in [0.0, 0.95]$, and every background pixel is strictly NaN. This file passes all 17 conformance criteria.
