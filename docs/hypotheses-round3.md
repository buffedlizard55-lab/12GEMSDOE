## Scope and non-duplication check

This register was checked against the mechanism inventory in [Round 2](hypotheses-round2.md#what-is-already-taken), the local scripts, and the sibling-source scope recorded in `evidence/history-sources.json`. It deliberately excludes previously tried raw/derived pixel classifiers, magnetic/gravity edges, basement/conductivity gradients, strain products, 1 m lidar scarps, radiometric ratios, Hough/Frangi ridges, tip rays, relay bridges, and geophysical coherence. This is an inspection-bounded claim: the two sibling repositories that previously returned 404 remain an unknown.

The public score target is **new fault pixels**, not geothermal vents. The competition page says that the test set is manually identified faults absent from the current database, and the staff clarification says a new fault may include previously unmapped geometry of an existing system. Nothing in this register claims that a candidate identifies a proven geothermal resource.

## Frozen H11 release rule

Do **not** spend a DrivenData weekly slot for H11 unless the `multi25_plus_h11` arm exceeds `multi25` by a positive mean paired DTI **and** wins at least 3 of 4 spatial folds under the exact H11 script/report. `multi25` is the current learned-model reference, not the numerical maximum of every control: the random 2% control is higher on this known-fault proxy and exposes that the proxy is not a private-label score. Therefore even a pass against multi25 would still require the stronger sibling-baseline and independent release gates. A loss, a one-fold gain, missing source hash, a training-label-derived feature, or a format-valid TIFF is not a release qualification.

## H11 measured validation — 2026-09-27

The feature was built **after** this register using `scripts/build_h11_drainage_feature.py` (source hash `bbdcf02168e9…`; output hash `554cbd381755…`). It uses B12/B19 only and declares `labels_used: false` in [`evidence/h11-feature-build.json`](../evidence/h11-feature-build.json). The frozen test was then run once via `scripts/holdout_round3_h11.py`; the complete machine-readable report is [`evidence/holdout_round3_h11.json`](../evidence/holdout_round3_h11.json) and its site copy is [`holdout_round3_h11.json`](holdout_round3_h11.json).

The paired H11 deltas are −0.00415, −0.00246, +0.00021, and −0.01047. H11 wins **1/4** folds and lowers mean DTI by **0.00421**, so it fails both preregistered conditions. The 3-pixel leakage probe was 0.0000 in every fold. **Decision: reject H11 as a submission upgrade; no GeoTIFF was packaged from H11 and no weekly slot was spent.**

This is a negative result on a known-fault proxy, not evidence that drainage deflections never map faults. It does mean this particular 100 m implementation is not justified as an addition to multi25 under the frozen protocol. Do not resurrect it by threshold tuning on these folds.
